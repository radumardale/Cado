## 📋 Contribution Policy

### ⚠️ Pre-Approval Required

**You MUST obtain explicit written approval before starting any work on this project.**

Unauthorized contributions will be rejected regardless of quality or usefulness.

#### How to Request Permission:

1. **Open an Issue First** - Do NOT submit a pull request without prior discussion
2. **Describe Your Proposal** - Clearly explain what you want to contribute and why
3. **Wait for Approval** - The project owner will review and explicitly approve or reject
4. **Get Written Confirmation** - Only proceed after receiving explicit "approved" confirmation

**Contact for Permission Requests:**
- Email: info@cado.md
- GitHub Issues: Use the "Contribution Request" template

## 🛠️ Contribution Guidelines

### If Your Contribution Request is Approved:

1. **Fork the Repository**
   - Only after receiving explicit approval

2. **Create a Feature Branch**
   - Branch from `develop` (not `main`)
   - Use naming convention: `feature/approved-issue-{number}-{description}`
   - Example: `feature/approved-issue-42-user-auth`

3. **Follow Code Standards**
   - TypeScript strict mode
   - Prettier formatting (run `npm run format` before committing)
   - Pass all type checks (`npm run typecheck`)
   - Ensure build succeeds (`npm run build`)
   - Follow existing code patterns and architecture

4. **Write Quality Code**
   - Self-documenting code with minimal comments
   - No security vulnerabilities
   - No breaking changes without explicit approval
   - Include tests where applicable

5. **Submit Pull Request**
   - Reference the approved issue number
   - Provide clear description of changes
   - Include before/after screenshots if UI changes
   - Ensure all CI checks pass

6. **Code Review Process**
   - The project owner has **sole authority** over code reviews
   - Multiple rounds of changes may be requested
   - Final approval is at the **sole discretion** of the project owner
   - Pull requests may be rejected for any reason or no reason

The following will be **immediately rejected**:

- Contributions without prior approval
- Code that violates the project's architecture or patterns
- Contributions that introduce breaking changes without approval
- Code with security vulnerabilities
- Contributions using GPL, AGPL, or other copyleft licenses

## 🔍 What We Look For

If you're seeking approval to contribute, we value:

- **Alignment with project goals** - Does it fit our roadmap?
- **Quality over quantity** - Well-crafted solutions, not quick fixes
- **No scope creep** - Stick to the approved scope
- **Respect for architecture** - Follow existing patterns
- **Clear communication** - Detailed proposals and explanations

## 📝 Bug Reports and Feature Requests

### Reporting Bugs

- Use GitHub Issues
- Include reproduction steps
- Provide error messages and logs
- Specify your environment (OS, Node version, etc.)
- **Note:** Submitting a bug report does NOT grant you permission to fix it

### Suggesting Features

- Use GitHub Issues with "Feature Request" label
- Explain the use case and benefits
- Provide examples or mockups if applicable
- **Note:** Feature suggestions do NOT guarantee acceptance or implementation
